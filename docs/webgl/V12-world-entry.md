## 3. WS Reconnect Race Condition (CRITICAL BUG)

### Problem
The WS close event fires BEFORE the ServerSelected message is processed by HandleServerMessage. Result: `_gameTicket` does not exist yet when the close handler checks -> reconnect never happens.

### Root Cause
WebSocket delivers close and data in the same frame. The close callback runs first.

### Fix: DeferredReconnect
```csharp
IEnumerator DeferredReconnect(VisualElement root, int closeCode)
{
    yield return null; // wait 1 frame -> data callbacks process first
    if (!string.IsNullOrEmpty(_gameTicket))
    {
        // reconnect with kqz
    }
}
```

## 5. Transcription Tool (120/120 = 100%)

`Tools/ClientAnalyzer/transcribe_methods.py`:

### Input
Type name (e.g. "fys", "ServerSelection", "fpm")

### Pipeline
1. **dump.cs**: finds methods with signatures and VAs
2. **decompiled_all.c**: match via 3 strategies:
   - Name match via batch grep (works for simple types like fys, fyr)
   - VA match via script.json RVA -> C function name (for obfuscated types with inner classes like fpm)
   - Direct grep for C definition (fallback for methods without VA)
3. **Parse**: extracts structured operations (CALL, SET_NAME, ADD_CLASS, FIELD_SET, IF, SWITCH, AWAIT, etc.)

## 7. World Entry Opcodes

After kvw (character select), the emulator sends 30+ opcodes:
- `kva`: character confirmed -> `_currentScreen = "World"`
- `kub`: characteristics (842b) — character stats
- `jru`: map load (field 2 = mapId) — NOT found in the actual burst
- `jss`: map actors response
- `lwt`: map terrain data (4068b) — the largest packet, likely cell data
- `jtg`: gift catalogue (2308b)

### Verified via Playwright

